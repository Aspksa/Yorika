# Восстановление резервной копии браузера Yorika

В **Настройки → Данные браузера** выберите **«Проверить копию JSON»**. Yorika проверит JSON и покажет число записей и разделов, не изменяя IndexedDB. Нажмите **«Восстановить без перезаписи»**, подтвердите действие: новые записи добавятся одной транзакцией IndexedDB. Если хотя бы один ID уже существует, вся транзакция откатится; существующие данные сохранятся.

Поддерживаются форматы `yorika-browser-data-v1` (из настроек) и `yorika-browser-export` версии 1 (из отдельного инструмента экспорта). Каждый раздел сверяется с разрешённым списком: settings, projects, memories, conversations, messages, tasks. У каждой записи должен быть уникальный в своём разделе непустой строковый ID. Максимум 100 000 записей и 50 МиБ файла на стороне интерфейса. Неподдерживаемые разделы отклоняются.

**Старые порты:** копия, полученная на другом origin, может быть вручную выбрана на новом адресе. Данные будут скопированы в IndexedDB текущего адреса. Экспортированная копия и старый origin не удаляются.

**Ограничения и безопасность:** восстановление не включает `localStorage` (например, настройки аватара или историю, сохранённую вне IndexedDB) из расширенного экспорта. Не загружайте неподтверждённые JSON-файлы: содержимое импортируется как данные. Восстановление не означает миграцию в Python SQLite и не подключает память к LLM. Файл проходит проверку формы, но пользовательский интерфейс ещё не проверен на реальном Windows-ноутбуке.
