# Этап 5: диагностика Cloud.ru и Windows DPAPI

Настройки → Cloud.ru теперь имеют **«Диагностика (без запроса к облаку)»** для проверки наличия сохранённого ключа и модели. Отдельная кнопка **«Проверить подключение»** выполняет фактический сетевой запрос к Foundation Models и может тарифицироваться. Никакие ключи не возвращаются из диагностики.

Обновлены ограничения файлового хранилища: символические ссылки вместо файла ключа или папки `secrets` отклоняются, а сохранение по-прежнему использует DPAPI CurrentUser и атомарную замену файла. Успешная проверка модели не означает, что ключ отзывается при локальном удалении.

Windows CI теперь запускает `test_windows_dpapi.py` с фиктивными ключами, проверяя шифрование, повторное чтение из отдельного процесса, смену модели и удаление. Регрессионный тест проверяет маршруты `/api/cloud-ru/*` и отсутствие ключа в ответах status/diagnostics/check. Ошибки 401/403/429 Cloud.ru отображаются коротко, без ключа и тела ответа провайдера.

**Ограничения и приёмка:** GitHub Actions до этого падал и журналы запусков выдавали 404; реальные тесты на Windows и авторизация живым ключом не подтверждены. Права NTFS наследуются от `%LOCALAPPDATA%`; отдельный аудит ACL и атаки из процессов того же пользователя остаются для тестирования на конечном ПК. Переменные окружения Cloud.ru используются как прежний резервный путь, поэтому удаление DPAPI-файла само по себе не отзовёт ключ, заданный в окружении.

Для приёмки на компьютере пользователя проверьте: сохранение ключа → закрытие и запуск Yorika → статус DPAPI → смена модели без повторного ключа → проверка соединения → удаление ключа → отсутствие секретов в файлах экспорта браузера и журнале.
