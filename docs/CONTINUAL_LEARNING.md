# Непрерывное развитие Yorika

Дата: 2026-10-19 UTC. Это единая программа из запроса владельца, с раздельными
статусами реализации. Обновление не превращает маленькую сеть в обученного собеседника.

## Работающий инженерный контур

На странице «Обучение» появился блок «Непрерывное обучение». Для включения нужны
PyTorch, выбранная собственная модель, исходный запуск с доступным неизменённым
учебным JSON и включённый сбор опыта. Выберите CPU или CUDA и сохраните режим.
Платных вызовов нет. Включение режима не включает Windows-планировщик ночи:
ночное расписание по-прежнему настраивается во вкладке «Ночь».

После сохранения ответа в SQLite браузер предлагает сбор опыта. Неоценённые ответы
попадают в очередь, а короткое обучение запускается после 👍 или исправления.
При занятом worker сбор откладывается до следующего диалога, ручного сбора или ночи.
Не каждый диалог становится обновлением весов: ошибки модели нельзя автоматически
принимать за правильные ответы. Во время активного обучения оценка следующего
ответа сохраняется, но отдельная новая работа не гарантируется до следующего триггера.

1. Происхождение исходных данных проверяется по manifest активного запуска.
2. Строятся постоянные группы по хешу нормализованного вопроса. Исправление ответа
   не переносит вопрос из проверочной группы в учебную. Пересечения с исходными
   экзаменами и учебными вопросами исключаются из нового опыта. Для исправления
   исходного корпуса нужен отдельный новый запуск; текущий цикл не меняет его.
3. Новый опыт чередуется с исходными учебными примерами и ранее усвоенным опытом.
   Окно повторения сдвигается между принятыми циклами, а не повторяет вечно первые строки.
4. До изменения весов создаётся проверенная SHA-256 копия. Токенизатор и архитектура
   сохраняются; AdamW начинает с новыми моментами. Это продолжение весов, не точное
   возобновление старого оптимизатора.
5. По умолчанию выполняется до 8 шагов с бюджетом обучения 60 секунд. Ночью —
   до 64 шагов / 600 секунд. CUDA не подменяется CPU при ошибке.
6. До и после обучения считаются NLL проверочного набора и набора удержания навыков.
   В каждом — до 64 исходных и до 64 новых примеров. Любое ухудшение отклоняет
   кандидата; требуется хотя бы одно строгое улучшение. NaN/Infinity отклоняются.
7. Принятый кандидат становится основой следующего **офлайн** цикла. Единственный
   активный checkpoint изменяется кнопкой «Выбрать проверенную версию». Перед
   выбором повторно проверяются хеши, исходная активная модель и актуальность опыта.
   Стандартная кнопка отката возвращает прежний указатель.

Копии и отчёты находятся в выбранной папке обучения, `continual/runs/<id>/`.
Отчёт содержит метрики и хеши, а не тексты разговоров. Неудачный цикл оставляет
активную модель и последний принятый офлайн checkpoint без изменений.

Границы: до 20 экспериментов и бюджет 2 ГБ с запасом на следующую работу.
Автоматического удаления нет. «Стоп всё» отключает новые циклы и выставляет stop;
работник проверяет его между шагами. Загрузка и оценка могут завершиться позже:
временной лимит относится к обучению, а не к полному процессу. После аварийного
завершения папку `continual/busy` удаляют только после проверки записанного PID.
Не удаляйте checkpoint, на который указывает active-brain.json, и нужные для отката версии.

Удаление/исправление опыта сбрасывает наследование офлайн головы при следующем
цикле. Это **не** гарантированное стирание информации из уже активных весов:
для такого удаления нужен отдельный чистый перезапуск обучения и новый экзамен.

## Экспериментальная архитектура

`backend/neural_adaptive.py` — отдельный лабораторный модуль, не подключённый
к действующему чату, центру обучения или стандартному загрузчику checkpoint.

- Один общий блок повторяется 1–8 раз без копирования его параметров. При обучении
  активации всё равно расходуют дополнительную память; улучшение рассуждений не доказано.
- Router выбирает два из 2–8 экспертов для каждого токена. Тест считает реально
  обработанные экспертами токены. Эксперты не получают заранее роли «счёт/речь»;
  роли должны появиться и быть измерены в обучении. Все веса занимают память.
- Внешние векторные слоты доступны через дифференцируемое внимание. Код проверяет
  градиенты, но не включает кодирование долговременной SQLite-памяти в эти слоты.
- `grown_copy()` добавляет остаточный блок с нулевым выходом: до обучения логиты
  совпадают с исходными. Проверено на CPU; произвольное изменение ширины или S→M
  без потери навыков не реализовано. После роста нужен новый оптимизатор.
- `weight_budget()` различает размер весов и нижнюю оценку памяти обучения.
  Для 200 млн параметров 4-битные веса — минимум 100 МБ, FP32 AdamW обучение —
  минимум 3,2 ГБ **до** активаций и буферов. Это не проверка совместимости с 4 ГБ.

## Все направления из запроса и честный статус

| Направление | Статус в этом обновлении |
|---|---|
| Частые микрообновления, копия и отклонение ухудшения | Реализован локальный контур после проверенной оценки; CPU-приёмка |
| Ночной повтор дня со старым | Новый контур подключён к существующему ночному циклу; Windows-планировщик требует устройства |
| Рост сети с сохранением выхода | Лабораторный рост глубины; миграция текущих checkpoint ещё не реализована |
| Быстрая память и навыки в весах | Проверенный опыт → обучение копии текущих весов; SQLite-память остаётся отдельной |
| Ослабление неважного | Ротация replay реализована; ранжирование по важности/частоте и управляемое забывание ещё нет |
| Любопытство / обучение на удивлении | Уже есть uncertainty в self_learning.py; новый автономный планировщик уроков не реализован |
| Повторный проход слоёв | Лабораторный блок, 1–8 проходов; качество надо измерить |
| MoE, два эксперта | Лабораторный top-2 router; нет обещания скорости или качества в 4–8 раз выше |
| 5–10 архитектур, эволюция и скрещивание | Не реализовано; произвольное слияние разных архитектур недопустимо |
| Самоигра с программным проверяющим | Не реализована; существующий Cloud.ru teacher-selfplay не является AlphaZero и может быть платным |
| Предсказание следующего сообщения | Не реализовано; высокий loss сам по себе не доказывает ошибку понимания |
| Поиск памяти внутри сети | Лабораторное внимание к векторам; связь с постоянной памятью требует обучения и оценки |
| Черновики, проверка, выбор ответа | Не реализовано; нужна независимая проверка, а не уверенность самой модели |
| 4-битный inference и облачное обучение | Реального INT4 backend нет; платное облако требует отдельного разрешения на запуск |

## Приёмка и следующий этап

Критерии узкого контура: токенизатор не меняется; веса действительно обновляются;
исходная копия сохраняется; регрессия/исключение не меняют активный checkpoint;
выбор ручной и обратимый; train и проверка не пересекаются; бюджет и stop доступны.
Критерии лабораторной архитектуры: causal attention; два экспертных назначения на
токен; градиент через память; неизменное число параметров при повторных проходах;
точное сохранение логитов при начальном добавлении блока.

Проверочные наборы этого цикла многократно используются для выбора. Это контроль
регрессии на выборке, **не независимый финальный экзамен** и не доказательство
сохранения всех знаний. Исходный test, включённый в retention, теперь тоже относится
к разработке: для публикации качества нужен новый закрытый финальный набор.

Следующий этап: реальная Windows/CUDA-приёмка, затем независимая арифметическая
самоигра с проверяющим и curriculum, затем обучение и сравнение лабораторной
архитектуры с dense baseline. Только после этого — миграция checkpoint, поиск
архитектур, подключение памяти, проверка черновиков и настоящий INT4 inference.

Научные ориентиры: [Switch Transformers](https://arxiv.org/abs/2101.03961)
и [QLoRA](https://arxiv.org/abs/2305.14314). QLoRA использует замороженные
квантованные базовые веса и обучаемые адаптеры; это не обучение случайных INT4-весов с нуля.

Проверка реализации этой ветки: Python 3.12, PyTorch 2.14.1+cpu, Linux.
`OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m unittest discover -s tests -v`:
324 теста, ошибок нет, 2 платформенных пропуска. Дополнительно после изменения
ночного replay повторены 10 тестов continual. `python scripts/check-plan.py`,
`node --check www/training.js`, `node --check www/avatar.js`, `git diff --check`.
Windows PowerShell runtime, реальная RTX 3050, качество обученного собеседника и
Cloud.ru не проверялись. NEURAL-008/009 остаются in_progress.
