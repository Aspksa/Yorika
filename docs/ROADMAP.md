# Yorika — живой план развития

> Статус: проектирование. Это план работ, а не заявление о реализованном ИИ.
> Канонические статусы машинно читаются из `planning/tasks.json`. Отмечать [x] здесь **только после доказательств**.

## CUDA checkpoint — запрет неподтверждённого переноса (PR #162)

- [x] **Device-bound exact resume:** каждый новый checkpoint фиксирует `training_device`; попытка продолжать CPU-состояние как CUDA-тренировку (или наоборот) блокируется. CUDA-resume обязательно требует сохранённое состояние CUDA RNG. Добавлены CPU регрессии и условные GPU проверки.
- [ ] **Многодневный CUDA-эксперимент и проверенный RTX 3050:** по-прежнему не выполнены; защита checkpoint не заменяет аппаратную приёмку.

## GPU — собственный CUDA-тренер (PR #161)

- [x] **Кодовая поддержка CUDA:** `run-language-experiment.py --device cuda` явно переносит единый BPE Transformer и обучающие тензоры на CUDA, восстанавливает AdamW и CUDA RNG, сообщает пиковую выделенную память. При отсутствии CUDA — явный отказ без скрытого CPU fallback.
- [x] **Тестовый CPU регресс и условный GPU тест:** CI проверяет CPU и отказ при недоступной CUDA; полноценный запуск CUDA теста требует реального GPU runner.
- [ ] **RTX 3050 приёмка, многодневное обучение, большой разрешённый корпус и доказанное качество:** всё ещё без фактических свидетельств, не отмечать выполненными.

## GPU — реальная диагностика до запуска (PR #160)

- [x] **Hardware preflight:** `PYTHONPATH=. python scripts/probe-language-cuda.py --output cuda-probe.json --require-cuda` проверяет настоящий доступ к CUDA, выполняет малое вычисление на устройстве и фиксирует GPU/VRAM; CPU CI проверяет достоверность отказа и не выдаёт preflight за обучение.
- [ ] **Полноценный CUDA тренер и многодневный эксперимент:** пока не реализованы в существующем CPU `neural_language_longrun.py`, поэтому hardware preflight не закрывает GPU milestone.
- [ ] **Большой разрешённый корпус и доказанное улучшение ответов:** прежний статус без изменений.

## Три главных незавершённых результата — приёмочные ворота (PR #159)

- [x] **Автоматическая проверка свидетельств:** `scripts/verify-language-readiness.py --records corpus.json --gpu-evidence gpu.json --dialogue-evidence human.json` отказывает при отсутствии доказательств: недостаточном числе разрешённых, проверенных человеком диалогов; отсутствии отчёта длительного CUDA запуска; отсутствии слепой независимой ручной оценки. Unit-тесты проверяют отказы.
- [ ] **Крупный качественный разрешённый корпус:** не получен и не аттестован; автоматическая проверка metadata не является лицензированием и не доказывает качество.
- [ ] **Длительное обучение на GPU:** не проводилось; GitHub CPU smoke не заменяет независимый многочасовой отчёт на RTX 3050.
- [ ] **Улучшение русскоязычного диалога:** независимые оценки людей не проведены; нельзя приравнивать снижение NLL к хорошему общению.
- Внешние JSON-свидетельства должны быть независимо проверены. Самозаполненные поля не являются криптографическим или аппаратным подтверждением. Этот PR не повышает активную модель и не оплачивает обучение.

## Первый этап — ограничение времени обучения (PR #158)

- [x] **Ограниченный запуск:** `scripts/run-language-experiment.py --max-run-seconds N` позволяет завершать очередной проход обучения после безопасной контрольной точки, сохраняет latest/best checkpoint и сообщает фактическое число шагов, секунд и шагов в секунду.
- [ ] **Длительный GPU-прогон:** новые лимиты и CPU-тесты не доказывают многодневного обучения RTX 3050, качества русского корпуса или улучшения диалога.

## Первый этап — финальная независимая приёмка (PR #157)

- [x] **Отдельная финальная команда:** `PYTHONPATH=. python scripts/finalize-language-test.py --records corpus.json --experiment-dir training-run` оценивает сохранённую лучшую модель только после завершения эксперимента. Повторная запись итогового отчёта запрещена.
- [x] **Связь данных и весов:** проверяет совпадение manifest с исходным разрешённым корпусом, SHA256 train и validation с checkpoint, непересечение prompts, хеш итогового best checkpoint; отчёт не содержит сами диалоги.
- [ ] **Доказанный интеллект:** NLL на отложенном test не доказывает качество русской речи. Многодневное RTX3050 обучение, большой лицензированный корпус и слепая ручная оценка всё ещё не выполнены.

## Первый этап — единый локальный эксперимент (PR #156)

- [x] **Исполняемая команда обучения:** `PYTHONPATH=. python scripts/run-language-experiment.py --records /path/to/consented.json --output /path/to/run --steps 100` — только явный локальный JSON корпус с consent, источником и разрешённой лицензией. Никакого автоматического скачивания данных, платного GPU или подмены активного мозга.
- [x] **Контроль эксперимента:** использует фиксированные train/validation/test, best/latest checkpoint, BPE и метрики trainer; создаёт отдельный JSON-отчёт и не перезаписывает существующий. Тестовый набор не используется для выбора checkpoint.
- [ ] **Приёмка масштаба и качества:** крупный разрешённый корпус не собран; многодневный RTX 3050 запуск, ручной аудит прав, конечный test и человеческая оценка диалога остаются открытыми.

## Первый этап — выбор лучшего checkpoint (PR #155)

- [x] **Отбор по validation:** длительный trainer сохраняет отдельный `.best.pt` только при снижении validation NLL; последнее состояние оптимизатора продолжает сохраняться независимо от лучшей версии.
- [x] **Продолжение и защита:** checkpoint фиксирует SHA256 validation, лучший шаг и лучший NLL; несовместимый набор оценки или отсутствие лучшего checkpoint запрещают восстановление. В CI добавлен фактический CPU PyTorch regression test.
- [ ] **Многодневное обучение и финальный независимый test:** ещё не выполнены; отбор лучшего по validation нельзя выдавать за измеренное улучшение качества реального общения. Активная модель автоматически не заменяется.

## Первый этап — независимое сравнение версий (PR #154)

- [x] **Независимый оценочный контур:** `backend/neural_language_benchmark.py` считывает два checkpoint одной версии BPE, проверяет совместимость словаря и зафиксированный SHA256 тестового набора, затем измеряет **взвешенные по токенам NLL и perplexity** без изменения рабочего мозга.
- [x] **Сохранность свидетельств:** отчёт JSON не содержит исходных реплик и создаётся без перезаписи предыдущего результата; CI добавлен реальный короткий PyTorch тренинг двух последовательных состояний и отдельная оценка.
- [ ] **Доказанное улучшение русского общения:** остаётся открытым до аудита большого разрешённого корпуса, долгого обучения на целевой машине, независимых человеческих и автоматических тестов на ранее неизвестных задачах. Снижение NLL на одном тесте не является доказательством высокого качества общения.

## Первый этап — масштабирование и долгий цикл (PR #153)

- [x] **Кодовая конфигурация 5–10 млн параметров:** 4-layer / width 320 / 8 heads / context 256 у BPE Transformer. Unit-тест проверяет число параметров. Это не подтверждение качества модели.
- [x] **Ограниченный long-run тренер:** `backend/neural_language_longrun.py` сохраняет optimizer, RNG, step, tokenizer и SHA256 тренировочных данных; делает периодические checkpoint и NLL на отдельной validation. При несовпадении исходных данных восстановление блокируется. Это кодовое восстановление, а не фактически выполненная многодневная тренировка.
- [x] **Гигиена учебного корпуса:** `backend/neural_corpus_v2.py` требует явный consent, источник/лицензию, запрещает повторные prompts и делает изолированный train/validation/test. Простая проверка PII/секретов не заменяет ручного аудита датасета.
- [ ] **Крупный качественный лицензированный русский корпус**, **длительное обучение на RTX 3050**, **независимый финальный test и доказанное улучшение диалога** — не подтверждены. Действующий checkpoint не заменён.

## Первый этап — BPE Transformer v2 (PR #152, технический срез)

- [x] **BPE-aware экспериментальный Transformer:** отдельный `backend/neural_language_bpe_v2.py` использует обученный исключительно на тренировочных парах byte-BPE, вычисляет маскированный loss на ответах, сохраняет словарь и проверяет checksum при загрузке. Реализованы heldout NLL и ограниченная генерация.
- [x] **Совместимость:** формат `yorika-language-bpe-v2` изолирован от `yorika-language-v1`; старые checkpoint не переключаются на новый словарь. Активная модель не заменяется автоматически.
- [ ] **Приёмка качества:** отдельные tests/CI не заменяют крупного лицензированного корпуса, многодневного обучения, сравнения метрик и Windows/RTX 3050 проверки. Широкие BRAIN-002/003/004 остаются открытыми до подтверждения их критериев.

## Дополнение первого этапа — обучаемая BPE-токенизация (PR #151)

- [x] **Исследовательский BPE-компонент (узкий функциональный срез):** `backend/neural_bpe_v1.py` обучает детерминированный byte-level BPE исключительно на явно переданных учебных строках; проверяет версию словаря и SHA-256; выполняет обратимое UTF-8 кодирование и декодирование. Реализация не собирает корпус и не обучает языковой Transformer.
- [ ] **BPE как часть рабочего мозга:** остаётся открыто до обучения новой модели с этим словарём, фиксации manifest и независимой проверки качества. `yorika-language-v1` checkpoint использует старый byte tokenizer и не совместим с новым словарём.
- [ ] **Крупный качественный разрешённый корпус, 5–10M параметров, длительное обучение и реальное улучшение русского диалога:** не выполнено; нужно подтвердить отдельными измерениями.
- **Тесты:** `tests/test_neural_bpe_v1.py`; CI-шаг добавлен, но реальные результаты внешнего runner и Windows/GPU ещё необходимы. Отметка [x] здесь ограничена наличием модуля, а не закрытием BRAIN-002 или DATASET-001 в машинном реестре.

## Cloud.ru — отдельный план интеграции

1. Сначала сделать локальное защищённое хранилище: `%LOCALAPPDATA%\\Yorika` и Windows DPAPI CurrentUser; секреты недоступны через `localStorage`, IndexedDB, JSON-экспорт и URL. Не отправлять Key Secret ни в GitHub, ни в чат.
2. Предпочитать сервисный аккаунт с минимальными правами и сроком действия ключа; при его отсутствии использовать персональный ключ Cloud.ru. Важно различать **Key ID + Key Secret** (для обмена на Bearer-токен) и отдельные API-ключи для сервисов, где они поддерживаются.
3. В интерфейсе: «Подключить» → безопасный ввод → «Сохранить на этом компьютере» → «Проверить подключение» → показать только маску идентификатора. «Удалить ключ» стирает локальные данные; отзыв доступа в самом Cloud.ru — отдельное действие.
4. Получать токен через официальный IAM API, не хранить и не журналировать токен в открытом виде. Обновлять по сроку действия, учитывать отказ, смену прав, отзыв ключа, сеть и тайм-аут.
