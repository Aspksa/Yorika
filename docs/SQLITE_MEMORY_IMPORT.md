# Безопасный импорт SQLite-памяти Yorika

Метод `Store.import_records(bundle, dry_run=True, on_conflict="reject")` принимает словарь, полученный через `Store.export_records(namespace)`. Он **не** изменяет базу по умолчанию: для применения требуется явно передать `dry_run=False`.

## 10 проверок и гарантий

1. Проверяется маркер формата `yorika-records-v1`.
2. Проверяется непустое пространство имён `namespace`.
3. `records` должен быть массивом не более 100 000 элементов.
4. Проверяется непустой строковый `record_id`.
5. Дубликаты идентификаторов в одном импорте отклоняются.
6. `value` обязан быть JSON-объектом; недопустимые числа `NaN` и `Infinity` отклоняются.
7. Проверяется непустая строка `updated_at`.
8. Импорт по умолчанию — только предварительный просмотр; возвращаются `requested`, `eligible`, `conflicts`, `applied`.
9. При `on_conflict="reject"` существующие ID останавливают импорт до записи. При `"skip"` существующие записи сохраняются неизменными; режим перезаписи отсутствует.
10. Новые записи добавляются одной транзакцией SQLite; непредвиденный конфликт прерывает всю транзакцию.

Пример:

```python
from backend.storage import Store
with Store() as store:
    bundle = store.export_records("memories")
    report = store.import_records(bundle)  # dry run only
    # Для импорта используйте другую чистую базу или явный on_conflict="skip".
```

**Ограничения:** импорт проверяет *формат* временной метки, а не парсит ISO8601; дополнительно защищайте источник бандла и проверяйте его происхождение. `on_conflict="skip"` при гонке с другим писателем откатывает транзакцию вместо частичного успеха. Это низкоуровневый локальный API, не пользовательский интерфейс и не восстановление всех данных браузера. Состояние MEMORY-005/DATA-002 не меняется; полная Windows-проверка остаётся необходимой.
