# Постоянный FTS5-индекс SQLite-памяти

`Store.ensure_memory_index()` создаёт виртуальную таблицу `memory_fts` и три SQLite-триггера в существующей локальной базе данных. При первом создании индекс заполняется существующими записями пространства `memories`, у которых поле `text` является строкой. Триггеры автоматически обновляют индекс при INSERT, UPDATE и DELETE; индекс сохраняется после перезапуска, а создание повторно идемпотентно.

`Store.search_memory_index(query, limit=20)` возвращает ранжированные результаты BM25 и не индексирует записи из других пространств имён. `scripts/recall-memory.py` использует постоянный индекс, а если сборка SQLite не поддерживает FTS5 — прежний поиск `Store.search_records()`. Данные не отправляются в облако.

**Совместимость:** основные таблицы и `PRAGMA user_version=1` не меняются. Индекс — производная структура, дополнительно хранимая в файле SQLite; при удалении или повреждении индекса необходимо обслуживать/перестраивать его отдельно. FTS5 и функции JSON1 должны поддерживаться сборкой SQLite. В индекс попадает **только строковое поле `text`**, а не вложенные текстовые значения JSON; старый `search_records_fts` по-прежнему доступен как временный полный индекс. Это лексический, не семантический поиск; полное Windows-тестирование не подтверждено.
