# Восстановление проверенной копии в отдельный файл

`scripts/sqlite_restore_copy.py` **не** заменяет рабочую базу. Утилита принимает созданную ранее самодостаточную SQLite-копию, проверяет её SHA-256, целостность и Yorika schema v1, копирует в НОВЫЙ файл и повторно проверяет результат.

```powershell
python scripts/sqlite_restore_copy.py "$env:USERPROFILE\Documents\yorika-backup.sqlite3" "$env:USERPROFILE\Documents\yorika-verified-copy.sqlite3" --sha256 "64_HEX_CHARACTERS_FROM_BACKUP_REPORT"
python -m unittest tests.test_sqlite_restore_copy -v
```

Требования: новый путь в уже существующей папке; файл назначения **не** должен существовать; оригинал не изменяется. Запрещено указывать живую базу `%LOCALAPPDATA%\Yorika\data\yorika.sqlite3` как место назначения. Для реального переключения базы необходимо отдельно остановить Yorika, проверить журналы WAL/SHM, сохранить предыдущую базу и пройти Windows restore-процедуру; этот CLI таких действий не выполняет.

**Границы:** скрипт не выполняет автоматический restart, не меняет установленную Yorika, не переносит DPAPI-ключи и не гарантирует защиту от постороннего процесса с доступом к той же папке. До проверки на Windows задача DATA-003 остаётся открытой. `DATA-006` — узкий этап безопасного восстановления в отдельный файл, без подмены текущей памяти.

## Дополнительная защита путей

Восстановление не раскрывает символьную ссылку в пути назначения перед проверкой существования и использует атомарное создание hard link без замены файла. При отсутствии соответствующих разрешений на файловую систему операция завершается ошибкой; fallback с небезопасной перезаписью запрещён. Проверка корректной работы NTFS/hard-link на настоящем Windows остаётся обязательной.
