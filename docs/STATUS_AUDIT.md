# Yorika — проверка документации и текущего состояния

Дата сверки: 2026-10-18. Основа: текущие исходники в main после PR №20. Это **аудит кода и документации**, не результат запуска на реальном Windows-компьютере.

## Проверенное по исходникам
- `Yorika.bat` и `scripts/yorika-tray.ps1`: существующий Windows PowerShell веб-сервер и трей.
- `www/avatar.js`, `www/settings.html`, `www/updates.html`: UI, аватар, настройки и обновления.
- `backend/storage.py`: код хранилища SQLite, транзакций и ручных резервных копий.
- `scripts/chat-store.py`: хранение истории через SQLite с номером ревизии и конфликтами записи.
- `www/avatar.js`: попытка загрузки и записи истории через /api/chat/history; локальный browser fallback.
- `www/memory-export.html`, `scripts/import-browser-memory.py`: ручной экспорт/архивный импорт данных текущего origin.
- `docs/CLOUD_RU.md`: проект Cloud.ru, **не работающий коннектор**; секреты и реальные ключи в репозиторий не загружались.

## Что НЕ подтверждено
- Windows PowerShell 5.1 runtime с Python и без Python; завершение и обратимость обновлений.
- Автоматическое восстановление всех предыдущих browser origins (случайные порты).
- Полный контроль гонок при нескольких вкладках и одновременной очистке; отсутствуют стабильные UUID сообщений.
- Реальная работоспособность и защищённость localhost API на машине пользователя.
- Собственная обученная с нуля языковая нейросеть, модель мира, самостоятельное обучение и проактивный планировщик.
- Рабочий Cloud.ru IAM, DPAPI-хранилище ключей, расходы и облачное обучение.
- Восстановление из резервной копии в реальных отказах, шифрование личных сообщений.

## Результаты сверки и решения
1. Старые тексты `README.md` и `docs/ARCHITECTURE.md` ошибочно подразумевали, что никакого SQLite / chat API пока нет. Их следует читать как старый snapshot, а актуальный статус — здесь и в исходниках.
2. Статус `DATA-001=in_progress` верен до Windows end-to-end тестов; `MEMORY-004=in_progress` до stress-тестов; зависимые этапы не закрывать.
3. `DOC-001` закрывается **только за этот документальный аудит и согласование правил**; он не означает успешных тестов функциональных задач.
4. GitHub Actions `.github/workflows/chat-memory-tests.yml` содержит тестовые команды, но доступная история CI для предыдущих ревизий имела ошибки, поэтому нельзя заявлять, что тесты прошли.
5. При следующей работе проверьте свежую ветку и все открытые задачи, затем устраните конкретный сценарий потери данных до расширения AI.

## Следующая приёмка
Реальное устройство Windows: два запуска с разными портами, диалог с кириллицей, пара вкладок с конкурирующими записями, очистка при конфликте, отсутствие Python, ошибки БД, backup/restore. Документировать команды и результаты; галочки ставить по факту.
