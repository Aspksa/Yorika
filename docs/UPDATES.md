# Обновление Yorika

Доступ: кнопка ☰ внизу слева → «Обновление».

Канал **Свежий** проверяет последний коммит main. Канал **Стабильный** проверяет последний опубликованный GitHub Release. Проверка по таймеру выполняется **только пока открыт сайт**. При обнаружении изменений отображается отметка в меню.

Приватный репозиторий требует GitHub personal access token с доступом на чтение Contents. Токен сохраняется в `.yorika/github-token.dpapi` с защитой DPAPI текущего пользователя Windows и не возвращается в браузер после сохранения. Токен доступен локальному приложению с правами того же пользователя; не считайте его защищённым от вредоносных программ под этой учётной записью.

По нажатию «Скачать и проверить» архив скачивается в системный каталог TEMP, проверяются состав и опасные пути внутри ZIP, затем вычисляется SHA-256. Проверенный пакет перемещается в `.yorika/staging/<sha>.zip`. Текущие файлы приложения при этом **не изменяются**.

**Важно:** этот этап реализует обнаружение и подготовку пакета. Автоматическая замена работающей версии и откат ещё НЕ включены: они требуют безопасной остановки процесса, резервного копирования, атомарного переключения и испытаний на Windows. До появления этих гарантий кнопки «Установить» нет. Не выдавать предварительную проверку структуры ZIP за криптографическую проверку происхождения пакета; hash считается для обнаружения последующих изменений файла, но не сверяется с подписанным манифестом GitHub.

Идентификатор установленного коммита пока неизвестен для скачанной вручную копии ZIP: при первой проверке может быть предложен существующий коммит как «доступный». Это ограничение будет устранено после введения версии сборки / installed manifest.

При переносе на другую учётную запись Windows токен DPAPI необходимо ввести заново. Конфигурация `.yorika/updates.json` переносима в пределах папки, но данные браузерной IndexedDB зависят от порта.

## Испытания
Необходимо проверить русские пути, работу с приватным токеном, сохранение и удаление, оба канала, поведение при отсутствии релизов, обновления в TEMP и запрет изменения рабочей версии. Эти сценарии ещё не пройдены на устройстве пользователя.

## Установка и откат (экспериментальный режим)

После подготовки архива появляется кнопка **«Установить обновление»**. Она требует отдельного подтверждения. Сервер отдаёт ответ и завершает работу. Внешний PowerShell-процесс ждёт остановки Yorika, повторно сверяет SHA-256 и распаковывает ZIP. Затем он создаёт резервную копию текущих файлов в `.yorika/backup-ГГГГММДД-ЧЧММСС`, не трогает `.yorika` и `.git`, заменяет файлы проекта и записывает `.yorika/installed.json`.

При ошибке копирования предусмотрена попытка автоматического восстановления файлов из резервной копии. Итог записывается в `.yorika/update-result.json`. После установки требуется **вручную запустить `Yorika.bat`**. Гарантий атомарности переключения каталога нет: операция выполняется путём копирования файлов и может быть прервана отключением питания или носителя.

Это **экспериментальный механизм**. Полноценные испытания на Windows, проверка обновления на заблокированных файлах, тест восстановления после отключения носителя, проверка подписи поставщика, а также автоматический перезапуск ещё не выполнены. Перед первым использованием рекомендуется сохранить копию папки проекта отдельно. Кнопка установки не появляется до подготовки проверенного архива.

## Изолированная проверка перед установкой

Добавлен `scripts/test-updater.ps1`. Скрипт создаёт небольшой тестовый репозиторий во временной папке Windows, формирует ZIP и манифест SHA-256, затем вызывает установщик в режиме `-TestOnly`. Проверяется положительный сценарий и обнаружение изменения ZIP после расчёта хэша. Текущая папка Yorika не изменяется.

Запуск из PowerShell в каталоге Yorika:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\test-updater.ps1"
```

Этот тест не проверяет реальную замену файлов, откат после частичного копирования или сценарии отключения питания. До успешных испытаний на тестовой копии использование кнопки «Установить» связано с риском повреждения рабочей папки.

## Интеграционные испытания установщика

Файл `scripts/test-updater.ps1` теперь содержит четыре испытания в изолированных папках системного TEMP:

1. Неразрушающая предварительная проверка ZIP.
2. Принудительная ошибка после удаления файлов тестового проекта и проверка отката из резервной копии.
3. Установка новой версии в тестовый каталог и проверка `installed.json`.
4. Изменение ZIP после вычисления SHA-256 и проверка отказа.

Тесты запускаются исключительно вручную в Windows PowerShell:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File ".\scripts\test-updater.ps1"
```

**Тесты добавлены в код, но ещё не запускались на пользовательском Windows.** Они не имитируют выключение питания, повреждение самого резервного каталога или полное исчерпание свободного места. Поэтому гарантия безусловного восстановления отсутствует.
