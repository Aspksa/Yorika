# ПРОВЕРКА YORIKA — запуск в один клик

Скачайте полный репозиторий Yorika и запустите файл **ЗАПУСТИТЬ_ПРОВЕРКУ.bat** в папке **ПРОВЕРКА_YORIKA** (она находится в корне проекта).

## Что происходит автоматически

1. Определяется папка проекта: никаких путей вручную вводить не нужно.
2. Скачивается официальный Python 3.12.10 для Windows x64 из `python.org` (только при первом запуске), распаковывается **внутри папки проверки**. Системный Python не используется.
3. Проверяются импорт SQLite и SSL.
4. Выполняется `scripts/run-acceptance.py`: план, память, резервные копии, многопоточные SQLite-тесты и набор Python unittest.
5. Если установлен Node.js, проверяется синтаксис `www/avatar.js`; если его нет, явно показывается, что JavaScript **не проверен**.
6. JSON-отчёт записывается на этом компьютере: `%LOCALAPPDATA%\YorikaTestReports\yorika-portable-acceptance.json`.

## Важно знать

- Нужны Windows 10/11 x64 и интернет при первой загрузке.
- Для обычных Python и SQLite проверок не требуются администраторские права, установленный Python, GitHub runner, Cloud.ru или отдельная флешка.
- Python embedded не включает pip. Тесты, требующие внешние пакеты, могут завершиться ошибкой; ошибки не скрываются.
- Встроенная проверка структуры ZIP не заменяет **криптографическую проверку SHA-256**. Контрольная сумма пока не закреплена; в корпоративной среде скачанный архив необходимо дополнительно проверять.
- Установка Python и запуск тестов происходят в вашей копии проекта. **Запускайте только проверенный код** и не предоставляйте скрипту доступ к корпоративным секретам.
- Эти проверки не подтверждают Windows DPAPI, браузерный UI, tray, настоящее подключение Cloud.ru и все GitHub Actions задания. Их нужно запускать отдельно.
- Папка `python312-runtime` и загружаемый ZIP не должны попадать в Git (они находятся в `.gitignore`).
- Если тесты не прошли, откройте JSON-отчёт или пришлите текст ошибки (без секретов). Зелёный результат означает успех Python acceptance, а не всего проекта.

## Дополнительно: GitHub self-hosted runner

Это локальная проверка, не автоматическая установка runner. Для ручного запуска CI сохранён workflow `.github/workflows/selfhosted-windows-acceptance.yml`, который требует отдельной настройки Python в окружении runner.
