# ЦЕНТР YORIKA — единый запуск разработки и проверок

Откройте папку **`ЦЕНТР_YORIKA`** в корне скачанного проекта и дважды нажмите **`ЦЕНТР_YORIKA.bat`**.

## Меню
1. **Проверить всё** — изменение файлов (только git-клон), затем Python/SQLite.
2. Проверить изменения Git.
3. Запустить Python и SQLite тесты.
4. Показать цветные статусы ранее запущенных проверок.
5. Сохранить локальный ключ Windows DPAPI.
6. Проверить наличие и возможность расшифровки локальных ключей.
0. Выход.

**Зелёный** означает реальное успешное завершение проверки; **красный** — ошибку; **жёлтый** — проверка пропущена. Результаты и время запуска сохраняются в `%LOCALAPPDATA%\YorikaDevelopment\status.json`, а полный Python JSON-отчёт — в `%LOCALAPPDATA%\YorikaTestReports\yorika-portable-acceptance.json`.

Секреты сохраняются **только** в `%LOCALAPPDATA%\YorikaDevelopment\secrets` с Windows DPAPI, привязаны к учётной записи и компьютеру. Значения ключей в отчётах, статусы и Git не записываются. Они не передаются автоматически в Cloud.ru или GitHub Actions; интеграция с отдельным хранилищем Cloud.ru требует отдельного безопасного подключения. На общем компьютере нужны отдельные учётные записи Windows; не копируйте папку secrets.

Python 3.12 embedded скачивается из `python.org` при первом запуске без использования системного Python 3.14. В версии загрузчика нет закреплённой SHA-256 контрольной суммы: при повышенных требованиях нужно сверить её независимо. Для сравнений файлов нужен полноценный git-клон, обычный ZIP позволяет выполнять Python/SQLite тесты, но не сравнение Git. Python embedded без pip может не обеспечить внешние зависимости. JS проверяется только при установленном Node.js. UI, Cloud.ru, CI и Windows DPAPI необходимо принимать отдельно.

GitHub CI находится в `.github/workflows/selfhosted-windows-acceptance.yml`. По соображениям безопасности он запускается **только вручную с проверенного main** на self-hosted Windows runner (метка `yorika-ci`), а не на PR. Требуется PowerShell 7 и Node.js.

Не считайте успех одной проверки свидетельством полной исправности Yorika: смотрите индивидуальные статусы и журнал тестирования.

## Если PowerShell запрещает выполнение сценариев

`ЦЕНТР_YORIKA.bat` проверяет политику PowerShell и показывает понятную подсказку вместо принудительного обхода запрета. В PowerShell выполните `Get-ExecutionPolicy -List`. Если компьютер управляется организацией, обратитесь к администратору за разрешённым способом выполнения проверенных или подписанных сценариев. **Не отключайте Kaspersky, не добавляйте небезопасные исключения и не используйте `ExecutionPolicy Bypass`.** После предупреждения Kaspersky сначала установите причину обнаружения; изменение политики не устраняет риск вредоносного кода.

### Почему все значения Undefined, но запуск запрещён

Если `Get-ExecutionPolicy -List` показывает `Undefined` во всех пяти областях, Windows PowerShell на Windows 10 обычно применяет эффективную политику `Restricted` по умолчанию. Это не означает, что сценарии можно запускать. Проверьте `Get-ExecutionPolicy` и отдельно `pwsh -NoProfile -Command "Get-ExecutionPolicy"`. BAT намеренно не изменяет системные настройки. До выяснения предупреждения Kaspersky **не меняйте политику для запуска Yorika** и не создавайте исключений антивируса. На корпоративном ПК согласуйте проверенные, подписанные скрипты с ИТ.
